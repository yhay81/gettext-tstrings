# অনুবাদ করুন গোটা বার্তা,<br>স্ট্রিংয়ের টুকরো নয়।

`gettext-tstrings` Python 3.14+ t-strings-কে প্রমিত gettext ক্যাটালগ আর Babel
টুলিংয়ের সঙ্গে জুড়ে দেয়। মান ও ফরম্যাটিং থেকে যায় অ্যাপ্লিকেশন কোডেই;
ক্যাটালগ ধরে রাখে সরল `{name}` placeholder-সহ একটি সম্পূর্ণ বার্তা:

```python
import gettext

from gettext_tstrings import Translator

_ = Translator(gettext.translation("messages", localedir="locales"))
name = "Ada"
print(_(t"Hello {name}"))  # with a Japanese catalog: こんにちは Ada
```

## এটি কি আপনার জন্য? { #is-this-for-you }

**আজই মানানসই, যদি** আপনার অ্যাপ্লিকেশন Python 3.14 বা নতুনতরে চলে; আপনি
আগে থেকেই gettext ও Babel ব্যবহার করেন, বা তাদের PO/MO ওয়ার্কফ্লো গ্রহণ করতে
চান; আর আপনি চান নাম-যুক্ত placeholder-সহ t-string সিনট্যাক্স, যেগুলি রেন্ডার
হওয়ার আগেই যাচাই হয়ে যায়।

**এখনও মানানসই নয়, যদি** আপনার Python 3.13 বা তার পুরনো দরকার হয়; আপনার একটি
স্থিতিশীল Python API লাগে — এটি একটি alpha, আর তার মধ্যে
[স্পেসিফিকেশন](spec.md)-ই থিতু হওয়া অংশ; কিংবা আপনার প্রায় সমস্ত অনুবাদযোগ্য
টেক্সট Python সোর্সে নয়, কোনও টেমপ্লেট ভাষায় থাকে।

আগে থেকেই ক্যাটালগ আছে? সেগুলি কাজ করতেই থাকবে।
`_("Hello {name}").format(name=name)` আর `tr(t"Hello {name}")` একই msgid তৈরি
করে, তাই বদলের পরেও বিদ্যমান অনুবাদ টিকে যায় —
[মাইগ্রেশন](migration.md) গোটা পথটিই দেখিয়ে দেয়।

## ক্যাটালগ কী বলতে পারে { #what-the-catalog-may-say }

ক্যাটালগ পায় সম্পূর্ণ বার্তাটি, `Hello {name}`। কোনও অনুবাদ `{name}`-এর ক্রম
বদলাতে বা তাকে পুনরাবৃত্তি করতে পারে, আর তার চারপাশের প্রতিটি শব্দ নতুন করে
লিখতে পারে। কিন্তু সে placeholder-টি বাদ দিতে পারে না, নতুন একটি বানাতে পারে
না, তার ভিতর দিয়ে আপনার অবজেক্টে হাত বাড়াতে পারে না, নিজের ফরম্যাটিংও জুড়তে
পারে না।

প্রতিশ্রুতিটি এইটুকুই: **কোনও অনুবাদ সে যে বার্তাটি অনুবাদ করছে তার কাঠামো
বদলাতে পারে না।** লাইব্রেরি তা যাচাই করে ঢোকার পথে — যখন ক্যাটালগ কম্পাইল হয় —
আর আবার রেন্ডারের সময়ে; তবুও ভাঙা কোনও এন্ট্রি প্রোডাকশনে পৌঁছে গেলে সে
সতর্কবার্তা লগ করে আর ক্র্যাশ না করে উৎস বার্তাটিই রেন্ডার করে।

!!! note "gettext নতুন লাগছে? গোটা ওয়ার্কফ্লো চার বাক্যে"

    **gettext** হল সফটওয়্যার অনুবাদের প্রমিত পদ্ধতি, Python-এ এবং তার
    অনেক বাইরেও। আপনার কোড অনুবাদযোগ্য বার্তাগুলি চিহ্নিত করে; একটি
    *এক্সট্র্যাক্টর* সেগুলি একটি টেমপ্লেট ফাইলে (`.pot`) জড়ো করে; একজন
    অনুবাদক — সচরাচর যিনি প্রোগ্রামার নন — প্রতি ভাষায় একটি করে ক্যাটালগ
    ফাইল (`.po`) পূরণ করেন, যা কম্পাইল হয়ে বাইনারি `.mo` হয় এবং আপনার
    অ্যাপ্লিকেশন রানটাইমে সেটি লোড করে। অনুবাদ ফাংশনের প্রচলিত নাম `_`,
    তাই `_(t"Hello {name}")` পড়া যায় "এই বার্তাটি অনুবাদ করো" হিসেবে।
    **[টিউটোরিয়াল](tutorial.md)** গোটা পথটাই — চিহ্নিত করা, এক্সট্র্যাক্ট,
    অনুবাদ, কম্পাইল, রান — প্রায় পাঁচ মিনিটে পার করিয়ে দেয়।

## এটি যে সমস্যার সমাধান করে { #the-problem-it-solves }

কোনও লাইব্রেরি একটি f-string দেখার আগেই সেটি ইন্টারপোলেট হয়ে গেছে —
`f"Hello {name}"` ততক্ষণে `"Hello Ada"` হয়ে গেছে, আর একটি মানের চারপাশের
টুকরোগুলি অনুবাদ করলে বেশিরভাগ ভাষার ব্যাকরণ ভেঙে পড়ে। একটি t-string
([PEP 750]) স্থির টেক্সট, মূল্যায়িত মান, উৎস এক্সপ্রেশন, কনভার্শন ও ফরম্যাট
স্পেক — সব আলাদা রাখে, আর একটি বার্তা ক্যাটালগের ঠিক এই বিভাজনটিই দরকার।
`%(name)s`, `.format()` ও `$`-strings-এর তুলনায়
[এতে কী বদলায়](comparison.md)।

তবে t-string থেকে বার্তা কীভাবে তৈরি হবে, gettext বা Babel কোথাও তা বলে না।
এই লাইব্রেরি সেই সিদ্ধান্তটি নেয়, তা একটি
[সংস্করণযুক্ত স্পেসিফিকেশন](spec.md) হিসেবে লিখে রাখে, এবং তা যাচাই করার
জন্য [কনফরম্যান্স সুইট](spec.md#conformance) সরবরাহ করে।

## নকশার নিয়মগুলি { #the-design-rules }

- সম্পূর্ণ বার্তার অনুবাদ, কখনও বাক্যের টুকরোর নয়।
- কেবল `{name}`-এর মতো সরল ভেরিয়েবল নাম গ্রহণযোগ্য।
- `!r` ও `:.2f` অ্যাপ্লিকেশনের নিয়ন্ত্রণে থাকে, ক্যাটালগের বাইরে।
- অনুবাদ পরিচিত placeholder-এর ক্রম বদলাতে ও পুনরাবৃত্তি করতে পারে, অথচ
  অ্যাট্রিবিউটে হাত বাড়ানো বা ফরম্যাটিং যোগ করা তার পক্ষে সম্ভব নয়।
- সাধারণ POT, PO ও MO ফাইল এবং সেগুলি যে টুল আগে থেকেই পড়ে, সবই যেমন আছে
  তেমনই পুনর্ব্যবহৃত হয়।

আর সে ইচ্ছাকৃতভাবে যা ছুঁয়ে দেখে না, তার মিলিয়ে দেখা তালিকাটি: সে সংখ্যা,
মুদ্রা বা তারিখ স্থানীয়করণ করে না — [সেগুলি আগে ফরম্যাট করে নিন](guide.md#locale-aware-values)
Babel দিয়ে; সে রেন্ডার করা আউটপুটকে HTML, শেল বা টার্মিনালের জন্য escape করে
না; আর কোনও অনুবাদ *সঠিক* কি না সে তা বিচার করতে পারে না, কেবল তার
placeholder অক্ষত আছে কি না তা-ই পারে।

## ইনস্টল { #install }

```console
python -m pip install gettext-tstrings
```

Python 3.14 বা নতুনতর দরকার। **রেন্ডারিংয়ের কোনও নির্ভরতা নেই** — এটি
স্ট্যান্ডার্ড লাইব্রেরির `gettext` ব্যবহার করে, আর কিছুই নয়।

এক্সট্র্যাকশন ও ক্যাটালগ যাচাই [Babel]-এর মাধ্যমে চলে, তাই সেই extra সেখানেই
ইনস্টল করুন যেখানে `pybabel` চলে — সচরাচর ডেভেলপমেন্ট বা CI পরিবেশ,
প্রোডাকশন ইমেজ নয়:

```console
python -m pip install "gettext-tstrings[babel]"
```

ট্র্যাকিং, যাঁরা gettext ও Babel সত্যিকারের কাজে ব্যবহার করেন তাঁদের কাছ থেকে
API পর্যালোচনা, এবং সমর্থিত প্রতিটি Python ও Babel রিলিজে সামঞ্জস্য পরীক্ষা।
