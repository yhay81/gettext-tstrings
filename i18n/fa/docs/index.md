# جمله را یک بار بنویسید.<br>و آن را یک‌جا ترجمه کنید.

یکپارچه‌سازی امن gettext و Babel برای t-string‌های پایتون 3.14 به بعد — مقدار
سر جای خود می‌ماند و کاتالوگ کل پیام را می‌بیند:

```python
import gettext

from gettext_tstrings import Translator

_ = Translator(gettext.translation("messages", localedir="locales"))
name = "Ada"
print(_(t"Hello {name}"))  # with a Japanese catalog: こんにちは Ada
```

[شروع آموزش :material-arrow-right:](tutorial.md){ .md-button .md-button--primary }
[چرا t-string؟](comparison.md){ .md-button }

این وب‌گاه همان چیزی را که مستند می‌کند به کار می‌بندد: هر نسخهٔ زبانی —
ناوبری، برچسب‌ها و گزارش ساختِ آگاه از صورت‌های جمع — به دست خودِ
[`gettext-tstrings`](https://github.com/yhay81/gettext-tstrings/blob/main/scripts/build_multilingual_docs.py)
از کاتالوگ‌های PO رندر می‌شوند.
{ .home-hero-note }

</div>

کاتالوگ جملهٔ کامل `Hello {name}` را دریافت می‌کند. ترجمه می‌تواند `{name}`
را جابه‌جا یا تکرار کند؛ اما نمی‌تواند آن را حذف کند، جای‌نگهدار تازه‌ای
بسازد یا قالب‌بندی از خود به آن بیفزاید — این کتابخانه همین را بررسی
می‌کند و کاتالوگ خراب به‌جای از کار انداختن برنامه، به متن مبدأ بازمی‌گردد.

!!! note "با gettext آشنا نیستید؟ کل گردش کار در چهار جمله"

    **gettext** روش استاندارد ترجمهٔ نرم‌افزار است، در پایتون و بسیار فراتر
    از آن. کد شما رشته‌های ترجمه‌پذیر را علامت‌گذاری می‌کند؛ یک
    *استخراج‌کننده* آن‌ها را در یک فایل الگو (`.pot`) گرد می‌آورد؛ مترجم —
    که معمولاً برنامه‌نویس نیست — برای هر زبان یک فایل کاتالوگ (`.po`) را
    پر می‌کند که به یک `.mo` دودویی کامپایل می‌شود و برنامهٔ شما در زمان
    اجرا آن را بار می‌کند. نام مرسوم تابع ترجمه `_` است؛ پس
    `_(t"Hello {name}")` یعنی «این جمله را ترجمه کن».
    **[آموزش](tutorial.md)** کل مسیر — علامت‌گذاری، استخراج، ترجمه،
    کامپایل، اجرا — را در حدود پنج دقیقه می‌پیماید.

## مسئله‌ای که حل می‌کند { #the-problem-it-solves }

یک f-string پیش از آن‌که هیچ کتابخانه‌ای آن را ببیند درون‌یابی شده است —
`f"Hello {name}"` دیگر به `"Hello Ada"` تبدیل شده، و ترجمهٔ تکه‌های اطراف
یک مقدار، دستور زبانِ بیشتر زبان‌ها را می‌شکند. اما t-string
([PEP 750]) متن ثابت، مقدارهای ارزیابی‌شده، عبارت‌های مبدأ، تبدیل‌ها و
مشخصه‌های قالب‌بندی را جدا از هم نگه می‌دارد — و این دقیقاً همان تفکیکی
است که یک کاتالوگ پیام لازم دارد.
[این چه چیزی را عوض می‌کند](comparison.md)، در مقایسه با `%(name)s` و
`.format()` و رشته‌های `$`.

با این حال، هیچ‌چیز در gettext یا Babel نمی‌گوید یک t-string چگونه به پیام
تبدیل شود. این کتابخانه آن انتخاب را انجام می‌دهد، آن را به شکل
[مشخصاتی نسخه‌دار](spec.md) مکتوب می‌کند و
[مجموعهٔ آزمون انطباق](spec.md#conformance) را برای راستی‌آزمایی‌اش عرضه
می‌کند.

## انتخابی که می‌کند { #the-choice-it-makes }

- ترجمهٔ پیام‌های کامل، نه هرگز تکه‌های جمله.
- پذیرفتن تنها نام‌های سادهٔ متغیر مانند `{name}`.
- نگه داشتن `!r` و `:.2f` زیر کنترل برنامه و بیرون از کاتالوگ.
- آزاد گذاشتن مترجم در جابه‌جایی و تکرار جای‌نگهدارهای شناخته‌شده — اما نه
  دسترسی به خصیصه‌ها و نه افزودن رفتار قالب‌بندی.
- استفادهٔ دوباره از فایل‌های معمولی POT و PO و MO، و ابزارهایی که همین
  حالا آن‌ها را می‌خوانند.

## نصب { #install }

```console
python -m pip install gettext-tstrings
```

پایتون 3.14 یا جدیدتر. **رندر هیچ وابستگی‌ای ندارد** — تنها از `gettext`
کتابخانهٔ استاندارد استفاده می‌کند و بس.

استخراج و اعتبارسنجی کاتالوگ از راه [Babel] انجام می‌شود؛ پس آن افزونه را
هر جا `pybabel` اجرا می‌شود نصب کنید — که معمولاً محیط توسعه یا CI است،
نه ایمیج عملیاتی:

```console
python -m pip install "gettext-tstrings[babel]"
```

## وضعیت { #status }

یک نسخهٔ آلفا. قرارداد عمداً کوچک است و [مشخصات](spec.md) بخش پایدار آن
است؛ APIِ پایتون هنوز ممکن است تغییر کند. پیش از انتشار پایدار، این پروژه
به فیکسچرهای زبانی گسترده‌تر، پایش مداوم کارایی، بازبینی API از سوی کسانی
که gettext و Babel را جدی به کار می‌برند، و آزمون سازگاری با همهٔ
نسخه‌های پشتیبانی‌شدهٔ پایتون و Babel نیاز دارد.

[ایشوها و پول‌ریکوئست‌ها](https://github.com/yhay81/gettext-tstrings/issues)
خوش‌آمدند — آلفا درست همان زمانی است که هنوز می‌ارزد بر سر رابط بحث کرد.
