# वाक्य एक बार लिखें।<br>अनुवाद पूरे वाक्य का करें।

Python 3.14+ के t-strings के लिए सुरक्षित gettext और Babel एकीकरण — value
अपनी जगह पर बनी रहती है, और कैटलॉग को पूरा संदेश दिखता है:

```python
import gettext

from gettext_tstrings import Translator

_ = Translator(gettext.translation("messages", localedir="locales"))
name = "Ada"
print(_(t"Hello {name}"))  # with a Japanese catalog: こんにちは Ada
```

[ट्यूटोरियल शुरू करें :material-arrow-right:](tutorial.md){ .md-button .md-button--primary }
[t-strings क्यों](comparison.md){ .md-button }

यह साइट वही करती है जो यह सिखाती है: हर भाषा संस्करण — नेविगेशन, लेबल,
और बहुवचन-सचेत बिल्ड रिपोर्ट — PO कैटलॉग से
[`gettext-tstrings` द्वारा ही](https://github.com/yhay81/gettext-tstrings/blob/main/scripts/build_multilingual_docs.py)
रेंडर किया जाता है।
{ .home-hero-note }

</div>

कैटलॉग को पूरा वाक्य `Hello {name}` मिलता है। अनुवाद `{name}` का क्रम बदल
सकता है या उसे दोहरा सकता है; लेकिन उसे छोड़ नहीं सकता, नया गढ़ नहीं सकता, और
अपनी ओर से फ़ॉर्मैटिंग नहीं जोड़ सकता — यह लाइब्रेरी इसकी जाँच करती है, और
टूटा हुआ कैटलॉग क्रैश करने की बजाय स्रोत टेक्स्ट पर फ़ॉलबैक करता है।

!!! note "gettext नया है? पूरा वर्कफ़्लो चार वाक्यों में"

    **gettext** सॉफ़्टवेयर के अनुवाद का मानक तरीका है, Python में और उससे
    कहीं आगे भी। आपका कोड अनुवाद-योग्य स्ट्रिंग्स को मार्क करता है; एक
    *एक्सट्रैक्टर* उन्हें एक टेम्पलेट फ़ाइल (`.pot`) में इकट्ठा करता है; एक
    अनुवादक — जो प्रायः प्रोग्रामर नहीं होता — प्रति भाषा एक कैटलॉग फ़ाइल
    (`.po`) भरता है, जो एक बाइनरी `.mo` में कंपाइल होती है और आपका
    एप्लिकेशन उसे रनटाइम पर लोड करता है। अनुवाद फ़ंक्शन का पारंपरिक नाम `_`
    है, इसलिए `_(t"Hello {name}")` को "इस वाक्य का अनुवाद करो" की तरह पढ़ा
    जाता है। **[ट्यूटोरियल](tutorial.md)** पूरे रास्ते — मार्क, एक्सट्रैक्ट,
    अनुवाद, कंपाइल, रन — को लगभग पाँच मिनट में तय कराता है।

## यह जिस समस्या को हल करती है { #the-problem-it-solves }

कोई f-string किसी भी लाइब्रेरी तक पहुँचने से पहले ही इंटरपोलेट हो चुका होता
है — `f"Hello {name}"` तब तक `"Hello Ada"` बन चुका है, और value के आसपास के
टुकड़ों का अनुवाद अधिकांश भाषाओं का व्याकरण तोड़ देता है। एक t-string
([PEP 750]) स्थिर टेक्स्ट, मूल्यांकित values, स्रोत एक्सप्रेशन, कन्वर्ज़न और
फ़ॉर्मैट स्पेक को अलग-अलग रखता है — और यही वह विभाजन है जिसकी संदेश कैटलॉग
को ज़रूरत होती है।
`%(name)s`, `.format()` और `$`-strings की तुलना में
[इससे क्या बदलता है](comparison.md)।

पर gettext या Babel में कहीं नहीं लिखा कि t-string संदेश कैसे बनता है। यह
लाइब्रेरी वह चुनाव करती है, उसे एक [संस्करणित विनिर्देश](spec.md) के रूप में
दर्ज करती है, और उसकी जाँच के लिए [कन्फ़ॉर्मन्स सुइट](spec.md#conformance)
भी देती है।

## यह जो चुनाव करती है { #the-choice-it-makes }

- हमेशा पूरे संदेशों का अनुवाद, वाक्य के टुकड़ों का कभी नहीं।
- केवल `{name}` जैसे सरल वेरिएबल नाम स्वीकार किए जाते हैं।
- `!r` और `:.2f` एप्लिकेशन के नियंत्रण में रहते हैं, कैटलॉग से बाहर।
- अनुवादक ज्ञात placeholders का क्रम बदल सकते हैं और उन्हें दोहरा सकते हैं —
  लेकिन attributes को कॉल नहीं कर सकते, और फ़ॉर्मैटिंग व्यवहार नहीं जोड़
  सकते।
- साधारण POT, PO और MO फ़ाइलें, और उन्हें पहले से पढ़ने वाले टूल, ज्यों के
  त्यों पुन: उपयोग होते हैं।

## इंस्टॉल { #install }

```console
python -m pip install gettext-tstrings
```

Python 3.14 या नया चाहिए। **रेंडरिंग की कोई निर्भरता नहीं है** — वह मानक
लाइब्रेरी के `gettext` का उपयोग करती है, और कुछ नहीं।

एक्सट्रैक्शन और कैटलॉग सत्यापन [Babel] के ज़रिए चलते हैं, इसलिए यह extra
वहाँ इंस्टॉल करें जहाँ `pybabel` चलता है — आम तौर पर विकास या CI परिवेश,
प्रोडक्शन इमेज नहीं:

```console
python -m pip install "gettext-tstrings[babel]"
```

## स्थिति { #status }

यह एक alpha है। अनुबंध जान-बूझकर छोटा रखा गया है और
[विनिर्देश](spec.md) उसका स्थिर हिस्सा है; Python API अभी बदल सकती है। स्थिर
रिलीज़ से पहले इसे और भाषाओं के fixtures, निरंतर प्रदर्शन ट्रैकिंग, gettext
और Babel के गंभीर उपयोगकर्ताओं से API समीक्षा, और हर समर्थित Python तथा
Babel रिलीज़ पर संगतता परीक्षण चाहिए।

[Issues और pull requests](https://github.com/yhay81/gettext-tstrings/issues)
का स्वागत है — alpha ही वह समय है जब इंटरफ़ेस पर बहस करना सार्थक होता है।
