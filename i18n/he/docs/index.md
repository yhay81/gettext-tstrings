# כתבו את המשפט פעם אחת.<br>תרגמו אותו בשלמותו.

אינטגרציה בטוחה של gettext ו-Babel עבור מחרוזות-t של Python 3.14+ — הערך
נשאר במקומו, והקטלוג רואה את ההודעה השלמה:

```python
import gettext

from gettext_tstrings import Translator

_ = Translator(gettext.translation("messages", localedir="locales"))
name = "Ada"
print(_(t"Hello {name}"))  # with a Japanese catalog: こんにちは Ada
```

[התחילו את מדריך המבוא :material-arrow-right:](tutorial.md){ .md-button .md-button--primary }
[למה מחרוזות-t](comparison.md){ .md-button }

האתר הזה מיישם את מה שהוא מתעד: כל מהדורת שפה — הניווט, התוויות
ודוח הבנייה המודע לצורות ריבוי — מרונדרת מקטלוגי PO על ידי
[`gettext-tstrings` עצמה](https://github.com/yhay81/gettext-tstrings/blob/main/scripts/build_multilingual_docs.py).
{ .home-hero-note }

</div>

הקטלוג מקבל את המשפט השלם `Hello {name}`. תרגום רשאי לשנות את סדר
`{name}` או לחזור עליו; אסור לו להשמיט אותו, להמציא מציין מקום חדש או לצרף
פורמט משלו — הספרייה הזו בודקת את זה, וקטלוג פגום נסוג לטקסט המקור במקום
לקרוס.

!!! note "חדשים ב-gettext? כל תהליך העבודה בארבעה משפטים"

    **gettext** הוא הדרך הסטנדרטית שבה תוכנה מתורגמת, ב-Python והרחק מעבר
    לה. הקוד שלכם מסמן מחרוזות הניתנות לתרגום; *מחלץ* אוסף אותן לקובץ
    תבנית (`.pot`); מתרגם — בדרך כלל לא מתכנת — ממלא קובץ קטלוג אחד
    (`.po`) לכל שפה, שמהודר לקובץ `.mo` בינארי שהיישום שלכם טוען בזמן
    ריצה. השם המקובל לפונקציית התרגום הוא `_`, כך ש-`_(t"Hello {name}")`
    נקרא כ"תרגם את המשפט הזה". **[מדריך המבוא](tutorial.md)** עובר את
    המסלול כולו — סימון, חילוץ, תרגום, הידור, הרצה — בכחמש דקות.

## הבעיה שהיא פותרת { #the-problem-it-solves }

מחרוזת-f כבר עברה אינטרפולציה לפני שכל ספרייה רואה אותה —
`f"Hello {name}"` כבר הפכה ל-`"Hello Ada"`, ותרגום המקטעים שסביב ערך שובר
את הדקדוק של רוב השפות. מחרוזת-t ([PEP 750]) שומרת את הטקסט הסטטי, הערכים
המחושבים, ביטויי המקור, ההמרות ומפרטי הפורמט בנפרד — וזו בדיוק ההפרדה
שקטלוג הודעות זקוק לה.
[מה זה משנה](comparison.md), בהשוואה ל-`%(name)s`, ל-`.format()`
ולמחרוזות-`$`.

שום דבר ב-gettext או ב-Babel לא קובע כיצד מחרוזת-t הופכת להודעה. הספרייה
הזו עושה את הבחירה, מתעדת אותה כ[מפרט מנוהל-גרסאות](spec.md), ומספקת את
[חבילת התאימות](spec.md#conformance) לבדיקתה.

## הבחירה שהיא עושה { #the-choice-it-makes }

- לתרגם הודעות שלמות, לעולם לא מקטעי משפטים.
- לקבל רק שמות משתנים פשוטים כמו `{name}`.
- להשאיר את `!r` ואת `:.2f` בשליטת היישום, מחוץ לקטלוג.
- לאפשר למתרגמים לסדר מחדש ולחזור על מצייני מקום מוכרים — אבל לא לגשת
  לתכונות, ולא להוסיף התנהגות פורמט.
- לעשות שימוש חוזר בקובצי POT,‏ PO ו-MO רגילים, ובכלים שכבר קוראים אותם.

## התקנה { #install }

```console
python -m pip install gettext-tstrings
```

Python 3.14 ומעלה. **לרינדור אין תלויות** — הוא משתמש ב-`gettext` מהספרייה
הסטנדרטית ותו לא.

החילוץ ואימות הקטלוגים רצים דרך [Babel], לכן התקינו את התוספת הזו בכל מקום
שבו `pybabel` רץ — בדרך כלל סביבת פיתוח או CI ולא תמונת ייצור:

```console
python -m pip install "gettext-tstrings[babel]"
```

## סטטוס { #status }

גרסת אלפא. החוזה קטן בכוונה, וה[מפרט](spec.md) הוא החלק היציב שבו; ה-API
של Python עדיין עשוי לזוז. לפני שחרור יציב נדרשים מקרי בוחן רחבים יותר של
שפות, מעקב ביצועים מתמשך, סקירת API מאנשים שמשתמשים ב-gettext וב-Babel
ברצינות, ובדיקות תאימות מול כל גרסאות Python ו-Babel הנתמכות.

[דיווחי תקלות ובקשות משיכה](https://github.com/yhay81/gettext-tstrings/issues)
יתקבלו בברכה — אלפא היא בדיוק השלב שבו עוד שווה להתווכח על הממשק.
