# لماذا t-strings؟

على كل طريقة لإدخال قيمة في رسالة قابلة للترجمة أن تجيب عن سؤال واحد:
*ما المقدار الذي ينبغي أن يتحكم فيه الكتالوج من لغة التنسيق؟* تختلف الإجابات
الأربع أدناه أيضاً في مصدر القيم وما يحدث عندما يغير الكتالوج عنصراً نائباً.

## التنسيق بعلامة %

```python
_("Hello %(name)s") % {"name": name}
```

يحمل نص الكتالوج صيغة printf، بما فيها حرف نوع أخير يسهل إغفاله وقد يتلف
بتعديل حرف واحد:

```pycon
>>> "Hello %(name)" % {"name": "Ada"}
Traceback (most recent call last):
  ...
ValueError: incomplete format
```

يكتشف `msgfmt --check-format` ذلك، لكن فقط للرسائل الموسومة
`python-format` وعندما يمر الكتالوج فعلاً عبر msgfmt.

## str.format

```python
_("Hello {name}").format(name=name)
```

يزيل حرف النوع الأخير مع إبقاء العنصر النائب مسمّى وقابلاً لإعادة الترتيب بحرية.

تكمن المشكلة في الجانب الآخر. `str.format` لغة تعبيرات صغيرة، واستدعاؤها على
نص يعني منح ذلك النص حق استخدام هذه اللغة:

```pycon
>>> "{name.__class__.__mro__}".format(name="Ada")
"(<class 'str'>, <class 'object'>)"
>>> settings.api_key = "sk-live-…"
>>> "{conf.api_key}".format(conf=settings)
'sk-live-…'
```

الكتالوج بيانات تمر عبر منصات وأشخاص كثيرين، ومع ذلك تمنحه `.format()` حق
الوصول إلى خصائص الكائنات الممررة.

## سلاسل `$` وflufl.i18n

```python
name = "Ada"
_("Hello $name")
```

توفر المكتبة القياسية لغة الاستيفاء `$name` عبر [`string.Template`][stdlib-template]، لكنها
ليست بحد ذاتها API للترجمة. يجمع [`flufl.i18n`][flufl-i18n] هذا الأسلوب مع البحث في
كتالوجات gettext. ويبني نطاق أسماء الاستبدال من المتغيرات العامة والمحلية
للمستدعي؛ وتكون لخريطة `extras` الاختيارية الأولوية على كليهما. لا تتضمن
الصيغة الموجهة للمترجم حرف نوع أخيراً أو محدد تنسيق، وتبقى العناصر النائبة
قابلة لإعادة الترتيب بحرية.

لا يثير الاستبدال غير المتاح استثناءً. مع `name = "Ada"` وعدم وجود `nombre`
في نطاق أسماء المستدعي، تُعرض ترجمة الكتالوج `Hello $nombre` على شكل
`Hello $nombre`، فيبقى العنصر النائب غير المحلول ظاهراً. يحافظ هذا
[السلوك الموثق] على بقية الرسالة المترجمة بدلاً من إفشال الاستدعاء. ومع ذلك،
قد تستمر الاستثناءات المثارة أثناء حل خاصية أو تحويل قيمة في الانتشار.

يتفوق `flufl.i18n` في جانب ذي صلة على `string.Template` المجرد. يقبل
[Template المخصص] الخاص به عناصر نائبة منقوطة مثل `$settings.api_key`،
ويحل [المترجم] تلك المسارات بالنسبة إلى قيم المستدعي. يمكن لعنصر نائب مترجم
تسمية أي متغير محلي أو عام متاح للمستدعي، واجتياز خصائصه باستخدام صيغة النقاط.
وهذا مناسب عندما تحتاج الرسالة إلى خاصية، لكنه يجعل إطار المستدعي أيضاً جزءاً
من نطاق أسماء الاستبدال للكتالوج. تصف المقارنة أدناه `flufl.i18n` 6.0.0،
لا كل استخدام ممكن لـ`string.Template`.

## t-strings

```python
tr(t"Hello {name}")
```

لا يزال الكتالوج يرى `Hello {name}` ويبقى كتالوج PO/MO عادياً. يختلف استخراج
المصدر: تتطلب الأدوات الحالية مستخرجاً يدرك t-string، مثل الذي توفره هذه
الحزمة. تُفحص الترجمة مقابل عناصر الرسالة المصدر النائبة وتعرضها هذه المكتبة،
التي لا تقبل إلا الأسماء البسيطة:

| ما تحتويه الترجمة | سبب الرفض |
| --- | --- |
| `{name.__class__.__mro__}` | placeholder `{name.__class__.__mro__}` must be a plain name, copied from the source message unchanged |
| `{name!r}` | placeholder `{name}` adds formatting; write `{name}` on its own, because the source message decides how the value is formatted |
| `{0}` | placeholder `{0}` must be a plain name, copied from the source message unchanged |
| `{nombre}` | translation does not match the source placeholders: `{name}` is missing; `{nombre}` is not in the source message |

يبقى التنسيق في التطبيق:

```python
amount = 1234.5
tr(t"Total: {amount:,.2f}")  # msgid is "Total: {amount}"
```

لا تصل `:,.2f` إلى الكتالوج أبداً.

## مقارنة مباشرة

| | `%(name)s` | `.format()` | `flufl.i18n` `$name` | `t"…"` |
| --- | --- | --- | --- | --- |
| العنصر النائب مسمّى | نعم | نعم | نعم | نعم |
| يمكن للمترجم تغيير الترتيب | نعم | نعم | نعم | نعم |
| مصدر القيم | خريطة صريحة | وسائط صريحة | متغيرات المستدعي العامة والمحلية، مع `extras` اختيارية لها الأولوية | الاستيفاءات التي التقطتها t-string |
| يتحكم الكتالوج في تحويل القيمة أو محدد التنسيق | نعم | نعم | لا | لا |
| يمكن للكتالوج طلب الوصول إلى الخصائص | لا | نعم | نعم، بأسماء منقوطة | لا |
| حذف عنصر نائب من المصدر عند العرض | يُحذف بصمت | يُحذف بصمت | يُحذف بصمت | يُعرض نمط المصدر كاملاً [افتراضياً](guide.md#what-happens-when-a-catalog-is-wrong) |
| عدم توفر عنصر نائب مضاف عند العرض | يثير استثناءً | يثير استثناءً | يبقى ظاهراً | يُعرض نمط المصدر كاملاً [افتراضياً](guide.md#what-happens-when-a-catalog-is-wrong) |
| فحص مجموعة عناصر المصدر النائبة وقت التشغيل (المفرد) | لا | لا | لا | نعم |
| علامة تنسيق PO التي يستنتجها Babel للمثال | `python-format` | `python-brace-format` | لا توجد | `python-brace-format` |
| يستخدم كتالوجات PO/MO عادية | نعم | نعم | نعم | نعم |
| يحتاج إلى مستخرج مصدر مخصص | لا | لا | لا | نعم، حالياً |

يتعلق صف علامة التنسيق بالتحقق المدرك للعناصر النائبة، لا بتوافق الكتالوج.
تعني `لا توجد` أن أدوات gettext القياسية لا تزال تقرأ الرسالة وتجمعها، لكن
`msgfmt --check-format` لا يملك قواعد لعناصر `$` النائبة كي يطبقها.

## التكلفة

لا يمكن استخدام f-string بهذه الطريقة مطلقاً؛ فحين تراها أي مكتبة تكون نصاً
مكتملاً بالفعل، ولذلك فإن ترجمتها تعني ترجمة جزء. توفر t-strings ([PEP 750])
هذا الفصل مع الحفاظ على صيغة تشبه f-string وربط القيم صراحةً. توفر سلاسل `$`
بالفعل بديلاً موجزاً بنموذج مختلف للربط والفشل. إن `flufl.i18n` حزمة ناضجة
يدعم إصدارها الحالي Python 3.10؛ أما `gettext-tstrings` فهي حالياً في مرحلة
alpha وتجعل t-strings الأصلية Python 3.14 حدها الأدنى.

الكلفة الأخرى هي القيد نفسه: يجب أن يكون الاستيفاء اسماً بسيطاً.

```python
tr(t"Hello {user.name}")  # rejected
```

```python
name = user.name  # compute it first
tr(t"Hello {name}")
```

هذا قيد حقيقي. وإلى جانب ربط القيم في المصدر وفحص العناصر النائبة وقت التشغيل،
يمنع نصوص الكتالوج من تقييم التعبيرات ويحافظ على أسماء عناصر نائبة ذات معنى.
