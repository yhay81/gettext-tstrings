# gettext-tstrings

Безопасная интеграция t-строк Python 3.14+ с gettext и Babel.

Напишите предложение один раз, на исходном языке, со значением на своём месте:

```python
import gettext

from gettext_tstrings import Translator

_ = Translator(gettext.translation("messages", localedir="locales"))
name = "Ada"
print(_(t"Hello {name}"))  # with a Japanese catalog: こんにちは Ada
```

В каталог попадает полное предложение `Hello {name}`. Перевод может переставить
или повторить `{name}`, но не может удалить его, добавить новый заполнитель или
собственное форматирование — библиотека это проверяет, а неверный каталог
откатывается к исходному тексту вместо сбоя.

!!! note "Впервые видите gettext? Весь процесс в четырёх предложениях"

    **gettext** — стандартный способ перевода программ, в Python и далеко за
    его пределами. Ваш код помечает переводимые строки; *экстрактор* собирает
    их в файл-шаблон (`.pot`); переводчик — обычно не программист — заполняет
    один файл каталога (`.po`) на язык, который компилируется в двоичный
    `.mo`, загружаемый приложением во время выполнения. Традиционное имя
    функции перевода — `_`, поэтому `_(t"Hello {name}")` читается как
    «переведи это предложение». **[Учебник](tutorial.md)** проходит весь путь
    — пометить, извлечь, перевести, скомпилировать, запустить — примерно за
    пять минут.

## Решаемая проблема

К моменту вызова любой библиотеки f-строка уже интерполирована —
`f"Hello {name}"` превратилась в `"Hello Ada"`, а перевод фрагментов вокруг
значения ломает грамматику большинства языков. t-строка ([PEP 750]) сохраняет
отдельно статический текст, вычисленные значения, исходные выражения,
преобразования и спецификации формата — именно такое разделение нужно каталогу
сообщений.
[Что это меняет](comparison.md) по сравнению с `%(name)s`, `.format()` и
`$`-строками.

gettext и Babel не определяют, как превратить t-строку в сообщение. Эта
библиотека фиксирует решение в [версионируемой спецификации](spec.md) и
поставляет [набор тестов на соответствие](spec.md#conformance).

## Принятые решения

- Переводить полные сообщения, а не части предложений.
- Разрешать только простые имена переменных, например `{name}`.
- Оставлять `!r` и `:.2f` под контролем приложения и вне каталога.
- Разрешать перестановку и повтор известных заполнителей, но не доступ к
  атрибутам и не добавление форматирования.
- Использовать обычные POT-, PO- и MO-файлы и существующие инструменты.

## Установка

```console
python -m pip install gettext-tstrings
```

Нужен Python 3.14 или новее. У рендеринга **нет зависимостей** — используется
только `gettext` из стандартной библиотеки.

Для извлечения и проверки каталогов нужен [Babel]. Установите extra в среде
разработки или CI:

```console
python -m pip install "gettext-tstrings[babel]"
```

## Этот сайт использует библиотеку сам

Документация — не просто переведённая демонстрация. Навигация, подписи темы,
строка copyright и отчёт сборки с множественными формами выводятся из
PO-каталогов самой `gettext-tstrings`.
[Многоязычный builder](https://github.com/yhay81/gettext-tstrings/blob/main/scripts/build_multilingual_docs.py)
в каждой строгой сборке выполняет контекстные сообщения, именованные
заполнители и правила множественного числа всех десяти языков.
