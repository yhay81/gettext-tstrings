# Зачем нужны t-строки

Любой способ подстановки значения в переводимое сообщение отвечает на вопрос:
*какую часть языка форматирования должен контролировать каталог?* Четыре
варианта ниже также различаются источником значений и поведением при изменении
заполнителя в каталоге.

## %-форматирование

```python
_("Hello %(name)s") % {"name": name}
```

В каталоге находится синтаксис printf, в том числе завершающая буква типа,
которую легко не заметить и можно повредить изменением одного символа:

```pycon
>>> "Hello %(name)" % {"name": "Ada"}
Traceback (most recent call last):
  ...
ValueError: incomplete format
```

`msgfmt --check-format` это обнаружит, но лишь для сообщений с флагом
`python-format` и только если каталог действительно проходит через msgfmt.

## str.format

```python
_("Hello {name}").format(name=name)
```

Завершающая буква типа исчезает, при этом заполнитель остаётся именованным и
может свободно переставляться.

Проблема находится с другой стороны. `str.format` — небольшой язык выражений,
и его вызов для строки даёт этой строке право использовать этот язык:

```pycon
>>> "{name.__class__.__mro__}".format(name="Ada")
"(<class 'str'>, <class 'object'>)"
>>> settings.api_key = "sk-live-…"
>>> "{conf.api_key}".format(conf=settings)
'sk-live-…'
```

Каталог проходит через платформы и людей как данные, однако `.format()` даёт
ему доступ к атрибутам переданных объектов.

## `$`-строки и flufl.i18n

```python
name = "Ada"
_("Hello $name")
```

Стандартная библиотека предоставляет язык интерполяции `$name` через
[`string.Template`][stdlib-template], но сам по себе это не API перевода. [`flufl.i18n`][flufl-i18n]
сочетает этот стиль с поиском в каталогах gettext. Пространство имён для
подстановки строится из глобальных и локальных переменных вызывающей стороны;
необязательное отображение `extras` имеет приоритет над ними. В синтаксисе для
переводчика нет завершающей буквы типа или спецификатора формата, а заполнители
можно свободно переставлять.

Недоступная подстановка не вызывает исключения. При `name = "Ada"` и отсутствии
`nombre` в пространстве имён вызывающей стороны перевод каталога
`Hello $nombre` отображается как `Hello $nombre`: неразрешённый заполнитель
остаётся видимым. Это [документированное поведение] сохраняет остальную часть
переведённого сообщения вместо сбоя вызова. Исключения при разрешении атрибута
или преобразовании значения всё же могут распространяться дальше.

В одном важном отношении `flufl.i18n` способен на большее, чем обычный
`string.Template`. Его [собственный Template] принимает заполнители с точками,
например `$settings.api_key`, а его [переводчик] разрешает такие пути по
значениям вызывающей стороны. Заполнитель перевода может назвать любую
доступную локальную или глобальную переменную вызывающей стороны и с помощью
точечной записи пройти по её атрибутам. Это удобно, когда сообщению нужен
атрибут, но одновременно делает фрейм вызывающей стороны частью пространства
имён подстановки каталога. В сравнении ниже описывается `flufl.i18n` 6.0.0, а
не все возможные способы использования `string.Template`.

## t-строки

```python
tr(t"Hello {name}")
```

Каталог по-прежнему видит `Hello {name}` и остаётся обычным каталогом PO/MO.
Извлечение из исходного кода отличается: современным инструментам нужен
экстрактор с поддержкой t-строк, например предоставляемый этим пакетом.
Перевод сверяется с заполнителями исходного сообщения и отображается этой
библиотекой, которая принимает только простые имена:

| Перевод содержит | Причина отклонения |
| --- | --- |
| `{name.__class__.__mro__}` | placeholder `{name.__class__.__mro__}` must be a plain name, copied from the source message unchanged |
| `{name!r}` | placeholder `{name}` adds formatting; write `{name}` on its own, because the source message decides how the value is formatted |
| `{0}` | placeholder `{0}` must be a plain name, copied from the source message unchanged |
| `{nombre}` | translation does not match the source placeholders: `{name}` is missing; `{nombre}` is not in the source message |

Форматирование остаётся в приложении:

```python
amount = 1234.5
tr(t"Total: {amount:,.2f}")  # msgid is "Total: {amount}"
```

`:,.2f` никогда не попадает в каталог.

## Сравнение

| | `%(name)s` | `.format()` | `flufl.i18n` `$name` | `t"…"` |
| --- | --- | --- | --- | --- |
| Именованный заполнитель | да | да | да | да |
| Переводчик может менять порядок | да | да | да | да |
| Источник значений | явное отображение | явные аргументы | глобальные и локальные переменные вызывающей стороны с необязательным переопределяющим `extras` | интерполяции, захваченные t-строкой |
| Каталог управляет преобразованием значения или спецификатором формата | да | да | нет | нет |
| Каталог может запросить доступ к атрибуту | нет | да | да, с именами через точку | нет |
| Исходный заполнитель удалён при отображении | молча пропускается | молча пропускается | молча пропускается | по умолчанию [полностью отображается исходный шаблон](guide.md#what-happens-when-a-catalog-is-wrong) |
| Добавленный заполнитель недоступен при отображении | вызывает исключение | вызывает исключение | остаётся видимым | по умолчанию [полностью отображается исходный шаблон](guide.md#what-happens-when-a-catalog-is-wrong) |
| Набор исходных заполнителей проверяется во время выполнения (единственное число) | нет | нет | нет | да |
| Флаг формата PO, выведенный Babel для примера | `python-format` | `python-brace-format` | отсутствует | `python-brace-format` |
| Использует обычные каталоги PO/MO | да | да | да | да |
| Требует специального экстрактора исходного кода | нет | нет | нет | да, сейчас |

Строка о флаге формата относится к проверке с учётом заполнителей, а не к
совместимости каталога. `отсутствует` означает, что стандартные инструменты
gettext по-прежнему читают и компилируют сообщение, но у
`msgfmt --check-format` нет грамматики `$`-заполнителей для применения.

## Цена

f-строку вообще нельзя использовать таким образом: к моменту, когда её видит
любая библиотека, это уже готовая строка, поэтому её перевод означает перевод
фрагмента. t-строки ([PEP 750]) обеспечивают разделение, сохраняя похожий на
f-строки синтаксис и явно привязывая значения. `$`-строки уже дают лаконичную
альтернативу с другой моделью привязки и сбоев. `flufl.i18n` — зрелый пакет,
текущий выпуск которого поддерживает Python 3.10; `gettext-tstrings` пока
находится на стадии alpha, а нативные t-строки задают минимум Python 3.14.

Другая цена — само ограничение: каждая интерполяция должна быть простым именем.

```python
tr(t"Hello {user.name}")  # rejected
```

```python
name = user.name  # compute it first
tr(t"Hello {name}")
```

Это реальное ограничение. Вместе с привязкой значений в исходном коде и
проверкой заполнителей во время выполнения оно не позволяет строкам каталога
вычислять выражения и сохраняет осмысленные имена заполнителей.
