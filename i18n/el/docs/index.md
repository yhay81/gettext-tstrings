# Γράψτε την πρόταση μία φορά.<br>Μεταφράστε την ολόκληρη.

Ασφαλής ενσωμάτωση των gettext και Babel για τα t-strings της Python 3.14+ —
η τιμή μένει στη θέση της και ο κατάλογος βλέπει ολόκληρο το μήνυμα:

```python
import gettext

from gettext_tstrings import Translator

_ = Translator(gettext.translation("messages", localedir="locales"))
name = "Ada"
print(_(t"Hello {name}"))  # with a Japanese catalog: こんにちは Ada
```

[Ξεκινήστε την εκμάθηση :material-arrow-right:](tutorial.md){ .md-button .md-button--primary }
[Γιατί t-strings](comparison.md){ .md-button }

Αυτός ο ιστότοπος εφαρμόζει όσα τεκμηριώνει: κάθε γλωσσική έκδοση —
η πλοήγηση, οι ετικέτες και η αναφορά build με επίγνωση πληθυντικού —
αποδίδεται από καταλόγους PO μέσω του
[ίδιου του `gettext-tstrings`](https://github.com/yhay81/gettext-tstrings/blob/main/scripts/build_multilingual_docs.py).
{ .home-hero-note }

</div>

Ο κατάλογος παραλαμβάνει την πλήρη πρόταση `Hello {name}`. Μια μετάφραση
μπορεί να αναδιατάξει ή να επαναλάβει το `{name}`· δεν μπορεί να το
παραλείψει, να επινοήσει άλλο ή να προσθέσει δική της μορφοποίηση — αυτή η
βιβλιοθήκη το ελέγχει, και ένας χαλασμένος κατάλογος επιστρέφει στο πηγαίο
κείμενο αντί να καταρρεύσει.

!!! note "Νέοι στο gettext; Όλη η ροή εργασίας σε τέσσερις προτάσεις"

    Το **gettext** είναι ο καθιερωμένος τρόπος με τον οποίο μεταφράζεται το
    λογισμικό, στην Python και πολύ πέρα από αυτήν. Ο κώδικάς σας επισημαίνει
    τις μεταφράσιμες συμβολοσειρές· ένας *εξαγωγέας* τις συλλέγει σε ένα
    αρχείο-πρότυπο (`.pot`)· ένας μεταφραστής — συνήθως όχι προγραμματιστής —
    συμπληρώνει ένα αρχείο καταλόγου (`.po`) ανά γλώσσα, το οποίο
    μεταγλωττίζεται σε ένα δυαδικό `.mo` που η εφαρμογή σας φορτώνει κατά την
    εκτέλεση. Το καθιερωμένο όνομα της συνάρτησης μετάφρασης είναι `_`, οπότε
    το `_(t"Hello {name}")` διαβάζεται ως «μετάφρασε αυτή την πρόταση». Η
    **[εκμάθηση](tutorial.md)** διατρέχει όλη τη διαδρομή — επισήμανση,
    εξαγωγή, μετάφραση, μεταγλώττιση, εκτέλεση — σε περίπου πέντε λεπτά.

## Το πρόβλημα που λύνει { #the-problem-it-solves }

Ένα f-string έχει ήδη υποστεί παρεμβολή τιμών μέχρι να το δει οποιαδήποτε
βιβλιοθήκη — το `f"Hello {name}"` έχει γίνει `"Hello Ada"`, και η μετάφραση
των τμημάτων γύρω από μια τιμή σπάει τη γραμματική των περισσότερων γλωσσών.
Ένα t-string ([PEP 750]) κρατά χωριστά το στατικό κείμενο, τις αποτιμημένες
τιμές, τις πηγαίες εκφράσεις, τις μετατροπές και τις προδιαγραφές
μορφοποίησης — που είναι ακριβώς ο διαχωρισμός που χρειάζεται ένας κατάλογος
μηνυμάτων.
[Τι αλλάζει αυτό](comparison.md), σε σύγκριση με τα `%(name)s`, `.format()`
και τις συμβολοσειρές `$`.

Τίποτα όμως στο gettext ή στο Babel δεν ορίζει πώς ένα t-string γίνεται
μήνυμα. Αυτή η βιβλιοθήκη κάνει αυτή την επιλογή, την καταγράφει ως
[εκδοσιοποιημένη προδιαγραφή](spec.md) και συνοδεύεται από τη
[σουίτα συμμόρφωσης](spec.md#conformance) για τον έλεγχό της.

## Η επιλογή που κάνει { #the-choice-it-makes }

- Μεταφράζει ολόκληρα μηνύματα, ποτέ αποσπάσματα προτάσεων.
- Δέχεται μόνο απλά ονόματα μεταβλητών όπως `{name}`.
- Κρατά τα `!r` και `:.2f` υπό τον έλεγχο της εφαρμογής, έξω από τον
  κατάλογο.
- Επιτρέπει στους μεταφραστές να αναδιατάσσουν και να επαναλαμβάνουν γνωστά
  σύμβολα κράτησης θέσης — αλλά όχι να καλούν ιδιότητες ούτε να προσθέτουν
  συμπεριφορά μορφοποίησης.
- Επαναχρησιμοποιεί συνηθισμένα αρχεία POT, PO και MO, και τα εργαλεία που
  ήδη τα διαβάζουν.

## Εγκατάσταση { #install }

```console
python -m pip install gettext-tstrings
```

Απαιτείται Python 3.14 ή νεότερη. **Η απόδοση δεν έχει εξαρτήσεις** —
χρησιμοποιεί το `gettext` της τυπικής βιβλιοθήκης και τίποτα άλλο.

Η εξαγωγή και η επικύρωση καταλόγων περνούν μέσα από το [Babel], οπότε
εγκαταστήστε αυτό το extra όπου εκτελείται το `pybabel`, δηλαδή συνήθως σε
περιβάλλον ανάπτυξης ή CI και όχι σε εικόνα παραγωγής:

```console
python -m pip install "gettext-tstrings[babel]"
```

## Κατάσταση { #status }

Έκδοση alpha. Το συμβόλαιο είναι σκόπιμα μικρό και η
[προδιαγραφή](spec.md) είναι το σταθερό του μέρος· το Python API μπορεί ακόμη
να αλλάξει. Πριν από μια σταθερή έκδοση χρειάζονται fixtures σε περισσότερες
γλώσσες, συνεχής παρακολούθηση επιδόσεων, αναθεώρηση του API από ανθρώπους
που χρησιμοποιούν στα σοβαρά τα gettext και Babel, και δοκιμές συμβατότητας
με κάθε υποστηριζόμενη έκδοση Python και Babel.

Τα [Issues και τα Pull Requests](https://github.com/yhay81/gettext-tstrings/issues)
είναι ευπρόσδεκτα — μια έκδοση alpha είναι ακριβώς η στιγμή που αξίζει ακόμη
να συζητηθεί η διεπαφή.
